## Architecture you'll need next time

- **The Listing is the marketplace conversion page.** Future coach-commerce work
  lands in `BSCoachDetailPublic` (`iosAppBroadsheetMarketplace.jsx`); the Signal
  living profile stays the identity surface. The `showProfile` early return builds
  the Signal person payload; `showCal` hosts the calendar; `realAvail` (null =
  demo/failed, `[]` = honestly none) gates real vs preview slots.
- **Availability path:** `provider_availability` weekly rows + requested/confirmed
  `sessions` → `GET /api/availability` (booked serialized as **ISO strings**) →
  `bsProjectAvailability({slots, booked, weeks})` — pure, local-time, past never
  emits, DST-normalized keys. One fetch feeds the station AND the calendar.
- **`d.role` on website living-profile payloads is LOWERCASE** — never compare to
  `"Nutritionist"`; normalize (`/nutritionist/i`) or use `roleLabel` for display.
- **Codex-filed PR threads never auto-resolve** — after fixing + replying, resolve
  via the GraphQL `resolveReviewThread` mutation; CodeRabbit auto-resolves its own
  on re-review. Poll scripts must filter CodeRabbit reviews to `submitted_at` newer
  than the fix push (the plain last-review state is stale on fix rounds).
