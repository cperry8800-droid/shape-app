## 2. The one piece of real work that is scoped, measured, and not started

**Author step durations for the recipe catalog.** This is the data half of #1910's round-6 P1
and it is the highest-value item on this list.

The engine now separates *how long a step takes* from *whether the cook may leave during it* —
`stepCost` in `cookOrchestrator.mjs` honours an authored `min` on **any** step, passive or not,
and `isWindow` is untouched, so a duration is never permission to walk away. The catalog does
not yet carry those durations. Verified this session by sweep:

- **444 of 471 steps** carry no authored duration.
- **122 of those state one in the prose.**
- **71 of 85 recipes therefore schedule short, by 1,817 minutes in total.**
- Worst: pot roast 127 min short, chicken pozole 99, baked pork chops 98, stuffed peppers 76,
  layered cheddar gratin 67.

The shape of the fix is a non-passive entry: `{ min: 70, passive: false, station: 'oven' }`.
There is a fixture test pinning exactly this in `tests/cook-serve-schedule.test.mjs`.

⚠ **Do not generate these by parsing the prose.** Measured and rejected this session:

- `Papaya banana batido`, a **ten-minute** smoothie, ends *"or cover and refrigerate up to 4
  hours before drinking"* — `bsStepTimers` reads that as a **240-minute step**. It is a
  shelf-life clause and nothing in the prose distinguishes it from a cook time.
- `Lentil and pearl barley soup` step 1 says *"simmer uncovered for **one hour**"* and parses
  as **nothing**, because the number is spelled out.

⚠ It touches `shapeKitchenData.js`, which **both open PRs edit**. Land it after they merge, or
expect a conflict in `_KITCHEN_STEP_META`.

In the meantime SERVE returns `estimated` and the prep sheet renders a caveat at the start
time — see §4.

## 3. Owner decisions outstanding (nothing should be built on a guess here)

1. **Tuna macros.** The USDA source publishes 5 oz tuna at 29 g protein × 4 servings for a dish
   holding ~40 g. Their own arithmetic is impossible. I withdrew the "High protein" tag but
   **left the numbers**, and all 100 USDA recipes carry their source's figures unmeasured.
   Needs a ruling on whether to restate or keep-and-attribute.
2. **"Get it all done soonest" is wired to SERVE, not TOGETHER.** Verified at source:
   `iosAppBroadsheetClient.jsx` returns `{ mode: BS_COOK_MODE.SERVE }` with no `serveAt` for
   that choice. The owner's stated intent is *"if you have to cook more than one, do them
   simultaneously to save waiting"* — which is TOGETHER's objective (minimise the session),
   not SERVE's (land everything at one moment). Measured: back-to-back 44.4 min; TOGETHER 38.6
   min, helping 45.3% of pairs; SERVE-at-earliest 39.9 min, helping 31.0%. **Product call.**
   (Those three figures were measured on #1910's branch, i.e. the 85-recipe catalog *before*
   #1911's windows land. The ranking is what matters, not the absolute minutes.)
3. **A third allergen class.** `Honey mustard pork chops` (unqualified commercial dressing) and
   `Beef and broccoli stir-fry` (oyster sauce) are currently *hidden* from the gluten-free
   filter. The catalog's convention elsewhere is keep-the-claim-plus-a-note. Whether these
   deserve an "ambiguous, buy a certified one" class is a ruling, not a patch.

## 6. Working notes that cost time to learn

- **Mutation-test with file copies, never `git checkout --`.** Commit first, `cp f f.bak`,
  mutate, restore from the backup. Run an unmutated sanity case **first and last**.
- ⚠ **A green test is not coverage.** This session's own new test was **hollow**: it asserted on
  `max(at + min)` and `evt` puts the authored `min` on the event whatever its passive flag, so
  reverting the fix left it green. Only mutation-testing caught it.
- ⚠ **Heredocs eat one level of backslash here**, even quoted ones — `'\\s'` reaches the file as
  `\s`, and a regex silently stops matching. Write scripts with the Write tool, or use
  `String.raw` so single backslashes suffice. Byte-verify with `cat -v` **on the line that
  actually carries the escape** — I checked the wrong line and believed a false zero.
- `gh` is not installed. GitHub work goes through the REST API with the token at
  `scratchpad/.tk`. Set `PYTHONIOENCODING=utf-8` or emoji in review bodies crash the print.
- Codex staleness: filter review comments on `original_commit_id`, never `commit_id`.
