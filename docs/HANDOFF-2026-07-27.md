## C1a — the shape, and the rules that govern it

`detail.days: [{dow, blocks}]` is **additive and optional**. `detail.blocks`
remains the DEFAULT menu that any unauthored day inherits, so every already-sold
plan behaves byte-identically with no backfill and no migration. `dow` 0 =
MONDAY. One normalizer, `bsPlanWeek(detail)` in
`mobile-app/src/services/planOutline.mjs`, serves **both** the coach Assign flow
(delivery) and the paid listing preview — a second implementation is how a
preview starts promising what delivery doesn't build.

Three rules came out of review and now govern that file:

1. **Delivery never truncates.** A display bound may truncate; a delivery bound
   may only ever truncate data that could not have been authored in good faith —
   and a 41st meal can be. The economy bound lives entirely in the preview, which
   is the only surface a crafted public-read row reaches unauthenticated.
   `perDay`'s *comparison* is bounded there too, because `bsPlanPreview` calls the
   normalizer **before** applying its own cap.
2. **A claim must be computed with the same semantics as the thing it claims
   about** — including the coercion. `perDay` backs the listing's "menus vary by
   day", so it compares *delivered* text: trimmed, empties dropped, falsy values
   dropped exactly as Assign's `mealsFrom` drops them.
3. **Writer and reader must scan the same entries.** Both take the first 7 raw
   `days`; a canonicalizer scanning further would promote an entry into the
   reader's window and change the menu a day serves.

Authoring is capability-gated to nutritionist `mealplan`/`diet` — never
`program` (those blocks are week ARCS and must never carry meals), never the
trainer paths that share the component. Both non-gated flows were verified
byte-identical to `main` by rendering and diffing the markup.

## New in the repo: a mount harness

`tests/broadsheet-render.test.mjs` compiles the broadsheet module in memory with
its **real** imports, renders through `ReactDOMServer`, and **drives** the
component (press a tab, fork a day, retype a meal, publish) via a `useState`
shim, since there is no react-test-renderer or jsdom here.

It exists because an adversarial pass proved static rendering wasn't enough:
dropping `days` from the publish payload, or changing the sparse-array lookup
from find-by-`dow` to index-by-position, **passed all 884 tests** — neither
changes the first paint. Suite is 892 now; the new tests are mutation-checked.

Reuse it for any broadsheet change touching hooks, effects or save paths.

## Open

- ⚠ **No published plan can be reopened for editing** — per-day or not.
  `openDraft` ignores the row it was invoked from and `publishDraft` only ever
  calls `ShapeCoachPlans.create`, so stored day menus are write-once in practice.
  Closing it needs the row's id + `detail` passed in (authored-empty days
  included), an update path, and a ruling on what a revision means for clients
  already assigned the old version. Registered in the contract's §8.
- **E (the entitlement layer) is NOT build-ready.** Open conditions: the
  coach-assigned path (no immutable assign-time record exists), whether "one
  active run" is per-discipline or global, **partial refund**, and **restoring a
  won dispute onto a reused slot**.
- **C1b / C2 / C3 not built.** C1b needs its AI contract; C2/C3 wait on E.
- Owner on-device pass for per-day authoring.

## Two failure classes worth carrying forward

**The publish callback is where a feature dies without erroring.** The editor
could track seven authored days perfectly and hand them to a callback that drops
the key — plan reloads as the legacy menu, nothing throws, every gate green.
Check every receiver destructures a new field, including ones the current flow
never triggers.

**Absence of data is not evidence of a promise.** In the entitlement spec,
keying grandfathering on `started_on IS NULL OR term_days IS NULL` would have
granted permanent free access to any row merely *missing* those fields — a
partial migration, a write-path bug, the unresolved coach-assigned path. One
round earlier the same predicate silently *revoked* access from legacy buyers.
Null semantics fail silently in both directions. Grandfathering keys on a stamp
the migration writes.
