## 3. Architecture you'll need

### 3a. Mobile habits page — `mobile-app/src/broadsheet/iosAppBroadsheetHabits.jsx`
- The page is **`BSHabitsPage`** → renders, in order: `BSHabitScoreCard`
  (the top "Earned today" plate), `BSHabitGrid`, then the To-do / To-don't
  `BSHabitSection`s. Add sheet = `BSHabitAddSheet`.
- **`BSHabitScoreCard({ habits, onOpenScore })`** — a `window.BSPlate` (teal). Shows
  today's earned/possible + ring + To-do/To-don't breakdown, and now a **"This week ·
  from habits"** row (`week.score` / `week.adherence`) before the "Tap to see your
  Shape Score →" line. Weekly numbers come from **`_bsHabitInsightStats(habits)`**.
- **`BSHabitGrid({ habits })`** — DO/DON'T × last-7-days; teal pill = done (`pattern`
  value `2` = today → full teal, `1` = full teal at `b3` alpha, `0` = `t.RULE` empty).
  Returns `null` when there are no rows (empty signed-in account). Day labels via
  **`_bsDow3()`** (3-letter), or the demo `_BS_HABIT_GRID_DAYS` when `model.demo`.
- **Data model functions (reused, not new):** `_bsHabitGridModel(habits)` →
  `{ days, rows:[{id,type,name,pattern,pts}], demo }`; `_bsHabitInsightStats(habits)`
  → `{ score, adherence, lastWeek, coach }`. **Demo path** (signed-out + no habits)
  returns the 14-row `_BS_HABIT_DEMO_ROWS` and score 156 / adherence 78; **signed-in
  with habits** computes from each habit's `history`. So in PREVIEW the grid/weekly
  reflect the seeded demo habits (sparse), not the canned 156/78 — that's expected.
- Habits persistence: `_bsUseServerHabits(tweaks, setTweak)` — live via
  `/api/client/habits` when signed in, ephemeral `tweaks.habits` otherwise; mirrors
  server state into tweaks so the home tracker stays in sync.

### 3b. Grocery — `mobile-app/src/broadsheet/iosAppBroadsheetClient.jsx`
- **`BSGroceryBuilder`** ("Build a list." custom-list page): aisle auto-sort lives
  here. State: `iAisle` + `aisleTouched`. `onNameChange(v)` sets `iAisle =
  bsBuilderAisleFor(v)` while `!aisleTouched`; a pill tap sets `aisleTouched=true`;
  `addItem()` resets both. AISLES = `['Produce','Protein','Pantry','Dairy &
  cold','Frozen','Bakery','Household']`.
- **`bsBuilderAisleFor(name)`** (module scope, near `bsGroceryAisleFor`): checks
  `BS_BUILDER_AISLE_RE` (Frozen/Bakery/Household) first, then falls back to
  `bsGroceryAisleFor` mapping `'Other' → 'Pantry'`.
- **`BSGrocery`** (the live grocery page): source-chip render is the `(() => {…src…})()`
  block — chip label is `src.label`, the middle name is suppressed when it equals
  the placeholder `"This week's plan"`. The Progress card is a `BSPlate c={rust}`.

### 3c. Website phone-mockup screenshot convention (GetApp + index)
- **`public/newdesign/GetApp.html`** — the walkthrough. Slides live in the inline
  **`STEPS` array** (`{kind,title,body,img,dark}`); the carousel renders dynamically
  from it (dots, count, dark/light phone). Phone frame: `.phone` (aspect `320/716`)
  → `.screen-crop img { object-fit: cover; object-position: center top }`.
- **`public/newdesign/index.html`** — landing loop. Beats are `.beat[data-i]`; phone
  = `.vis` (aspect `320/716`) → `.vis .scr img { object-fit: cover; … }`.
- **Screenshot assets** (`public/newdesign/getapp-*.png`) are **clean screen-only**
  captures (no device frame, no notch) at **600×1387** (aspect 0.433). The phone
  frame aspect `320/716` makes them fit edge-to-edge with `cover` (no letterbox).
  `getapp-chat-v2.png` is 408×861 (the community feed) — crops ~4% on the sides
  under `cover`, acceptable. **Bump the `?v=` on an image only when its bytes change.**

### 3d. Reusable headless-screenshot pipeline (rebuilt this session)
The mobile app *can* be rendered headless to verify a screen visually:
- **Chrome is cached** at `~/.cache/puppeteer/chrome/linux-*/chrome-linux64/chrome`;
  **puppeteer + puppeteer-core live in `/tmp/node_modules`** (so run capture scripts
  from `/tmp`, e.g. `cd /tmp && node caphabits3.mjs`). Network for fonts/unpkg may be
  blocked — layout still renders fine.
- Serve the built app: from `public/`, `python3 -m http.server 8099` →
  `http://localhost:8099/m/`.
- **Gate flow to reach the app (preview mode):** click `Preview the app` →
  `Step inside` (text-match clicks). A one-time **Radio interstitial** ("Want music
  while you move?") otherwise covers the screen — **suppress it** by seeding
  localStorage *before* nav:
  `page.evaluateOnNewDocument(() => localStorage.setItem('shape.radio.pref',
  JSON.stringify({asked:true, on:false})))`.
- To open the habits page: click text `Daily habits` (home agenda card). Screenshot
  the clean inner screen via `await page.$('#bs-phone-surface')` → `.screenshot()`.
- Working example scripts are in `/tmp/caphabits3.mjs` (and `/tmp/cap.mjs` for the
  gate-nav helper). These are scratch — **container-ephemeral**, not committed.

## 4. Verify-before-ship loop (MANDATORY)

```bash
# Mobile JSX parse-check (babel lives in mobile-app):
cd mobile-app && node -e "require('@babel/parser').parse(require('fs').readFileSync('src/broadsheet/iosAppBroadsheetHabits.jsx','utf8'),{sourceType:'module',plugins:['jsx']});console.log('OK')"

# Mobile build + republish (run the cp from REPO ROOT in its own Bash call):
cd mobile-app && VITE_BASE=/m/ npm run build
cd /home/user/shape-app && rm -rf public/m && cp -r mobile-app/dist public/m

# Tests / TS / Next (when touched):
npm test          # expect 104 pass
npx tsc --noEmit
npm run build
```
The tracked **pre-commit hook** (`.githooks/pre-commit` → `scripts/verify-staged.sh`)
runs the right subset automatically on `git commit` and **blocks on failure** — it
ran green for every commit this session. HTML/PNG-only commits are treated as
docs/assets ("no code staged") and skip the build/test gate.

**Gotchas re-confirmed this session**
- `cp -r mobile-app/dist public/m` **must run from repo root** in its own Bash call —
  a prior `cd mobile-app &&` in the *same* command makes `cp` fail with
  `cannot stat 'mobile-app/dist'`.
- **Don't `pkill -f` in the same Bash command as a `git commit`** — it killed the
  shell mid-commit once (exit 144); run cleanup separately.
- Foreground `sleep` is blocked; use `run_in_background: true` to pace CI polling.
- CI on a pure HTML/PNG PR still runs both required checks (no path filter in
  `ci.yml`), but they register a few seconds after the Vercel checks — don't assume
  they're skipped if only Vercel shows up immediately.

### Ship discipline
Per change: commit → push to the dev branch → open PR → wait for the two required
checks (Web + Mobile) green → squash-merge → re-sync dev to main
(`git fetch origin main && checkout main && reset --hard origin/main && checkout
<dev> && reset --hard origin/main && push --force-with-lease`). The non-required
**Build debug APK** check is occasionally flaky (transient SDK download) — re-run it,
don't block on it. Commit trailer: `https://claude.ai/code/session_01S5E4KXsqAeV21zqWu7cMv4`.
**Never** put a model id in commits/PRs/code.
