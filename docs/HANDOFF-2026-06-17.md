`main` and the session's `claude/*` dev branch are kept **identical** (every PR
squash-merges to main, then the dev branch is force-reset to main AND **pushed**).
Treat `origin/main` as the single source of truth. **The web container
periodically resets the working tree to an older commit**, so at the start of any
new turn run (two separate rev-parses — the combined form errors):
```
git fetch origin main && git rev-parse --short HEAD && git rev-parse --short origin/main
```
If HEAD ≠ origin/main, `git reset --hard origin/main` before editing.

> **Stop-hook gotcha (learned this session):** the git stop-hook compares
> `origin/<dev-branch>..HEAD`. After a squash-merge + `checkout -B <dev>
> origin/main`, you **must also push the dev branch** (`git push --force-with-lease
> origin <dev>`) — otherwise the GitHub squash-merge commit looks "unpushed /
> Unverified". Do NOT `--amend --reset-author` it: that's GitHub's merge commit
> (committer `GitHub <noreply@github.com>`), and amending diverges dev from main.
