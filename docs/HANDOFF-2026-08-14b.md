## 3. What #1880 contains now (security only)

- **RLS on `sessions`** — `client_cancel_sessions` is `requested|confirmed → cancelled` only.
  A `BEFORE UPDATE` trigger freezes the booking **wholesale** via an allowlist
  (`to_jsonb(new) - 'status' - 'updated_at'`), so a column added later is frozen by default.
- **The provider policy it depends on.** Permissive policies OR-combine **per phase**: an
  UPDATE passes if ANY policy's USING admits the old row and ANY policy's WITH CHECK admits
  the new one — *not necessarily the same policy*. `2026-04-18` declared
  `provider_update_sessions` with `with check (true)`, which would OR past the whole fix on a
  rebuild-from-files. Both the new migration and the historical file now converge.
- **Open-redirect sweep, 7 sites.** `/\evil.example` clears a `startsWith('/')` check and
  browsers normalise the backslash into a protocol-relative jump. Four server sites now call
  `safeReturnPath` (`src/lib/safe-redirect.mjs`, from #1471 — it already existed and its own
  comment falsely claimed to "mirror" the inline guards); three client copies that cannot
  import it restate the rule.

## 4. The P1 that was live on production

Worth reading in full before touching that trigger again.

The provider exemption originally checked the **NEW** row's provider, with a comment saying
that stopped "a repoint away from their own row". True, and the wrong direction — it let a
caller repoint a booking **TO** their own listing and be exempted for it.

Not exotic here: **coaches are members**, so anyone with an approved listing who books another
coach is simultaneously the client and a provider owner. As that caller, one PostgREST UPDATE
moved `provider_id` to their own listing, set `status='confirmed'`, reassigned `client_id` to a
**different member** and set an attacker-controlled `meeting_url` — attaching a confirmed
session, with a link they control, to someone who never booked it.

Fixed by keying the exemption on the **OLD** row's provider and freezing `provider_id`,
`provider_role` and `client_id` even for the coach: *owning a booking is not the same as owning
who it is with.*

Nothing was exploited — `sessions` has 0 rows; this was closed before first use.

## 6. Why the split happened

Findings per round: **3 → 3 → 4 → 3 → 1 → 1**. Flat through round four. The repo's own rule
(`the-miss-is-next-to-the-fix`) says a flat curve means *change approach, not patch again*.

Every round, the auth-return-path thread produced findings, and it kept widening: consultation
→ `/login` → `login.html` → `signup-client.html` → `/signup` → `SignupForm` → `/auth/callback`
→ `supabase.js`, across two parallel signup implementations. None of it was the security sweep's
subject. The owner chose to split; the curve dropped immediately, and the one finding that came
after the split was a real security bug (§4) rather than scope drift — which is the evidence the
split was right.

**The security half was never the problem.** Keep them apart if this recurs.

## 7. Lessons worth carrying

- **A because-clause is a claim, and it can be backwards.** The P1's comment correctly described
  one direction and missed its mirror. Two separate comments this session asserted mechanisms
  that were false; both were corrected rather than softened.
- **Enumerating fields is a losing game.** The field freeze named five columns and left six
  writable, including the coach's own `notes`. The allowlist (`to_jsonb(...) - 'status'`) is the
  shape that survives a new column.
- **The repo cannot reproduce production's security posture.** `provider_update_sessions` is
  owner-scoped live but was `with check (true)` in the migration file — same class as the
  already-registered `trainers`/`nutritionists` anon-read policies. **Verify live; do not read
  the file and conclude.**
- **A guard must be mutation-tested, and a loose guard cannot be tightened until its parser is
  right.** The `pg_temp` check took three rounds: substring → list-shaped capture → exact
  element match. The exactness was only *safe* once the capture stopped swallowing trailing
  modifiers.
- **An absent review is not a clean review**, and `commit_id` re-anchors forward — filter on
  `original_commit_id`.
