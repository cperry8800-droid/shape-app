## Traps this session paid for

- **A because-clause is a claim — and it is not just a code comment.** Six comments in
  #1869 asserted a false mechanism, including **one written to fix the previous false
  one**, and one citing a "step 5" in a four-step file. Then the same error escaped
  the source: the changelog called an advisory job a "required CI check", and told a
  future session a cut checker was "re-landable verbatim" two sentences after listing
  its seven defects. **Codex caught both on the docs PR.** Records are gated more
  weakly than code, so a false claim there survives longer.
- **The miss is next to the fix.** Rounds 6–12 were *all* inside the checker added to
  answer round 5, several fixing the prior round's fix. Findings ran 3·1·3·2·1·2·3 —
  **no decay**. A flat curve across three rounds means the mechanism is wrong, not the
  instance. I read it as converging for three rounds longer than the evidence
  supported; cutting the file is what ended it. **Cut earlier.**
- **Two guards written to ban enumeration were themselves enumerations.** If a rule
  says "don't list the cases", the test for it must not list them either.
- **Verify a scripted patch landed.** Two patch scripts reported success while
  silently no-op'ing — one printed `patched` unconditionally, one applied 2 of 4
  replacements and left a variable undefined. Both were caught by *running* the
  result, not by reading the output. Every patch script today counts its matches and
  aborts unless each is exactly 1.
- **Backticks in a double-quoted bash string get evaluated.** It ate three code spans
  out of the #1870 body. Write PR/comment bodies to a file, then read the file.
