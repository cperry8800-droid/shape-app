## 3. The next work, scoped and measured: the i18n wave

`tests/i18n-surface-inventory.test.mjs` walks `mobile-app/src/broadsheet/*.jsx` with the AST and
reports, per **component** (never per file):

- **358** components render JSX — **84 fully localized · 31 partial** (193 strings still
  hardcoded) · **125 with no translator in scope at all** (1,355 strings) · 118 render no copy.
- Of the **240** that render copy, **35%** are localized.

The uncovered set is not the tail; it is the product. Four cuts are registered, in the order a
member meets them.

### Cut 1 — the launch / auth shell (~107 strings, all in one file)

**`BSLanguagePicker` is the only localized screen in the entire launch flow** (3 `tr()`, in its
own file). Every screen on either side of it carries none — verified against the stage machine
(`beat → lang → gate → … → daily`), not assumed. So a member picks Spanish and the very next
screen, and every screen until the app itself, is English.

All in `mobile-app/src/broadsheet/iosAppBroadsheetMain.jsx` (2,474 lines):

| Component | Line | Strings |
|---|---|---|
| `BSSplash` | 555 | 35 |
| `BSLogin` | 959 | 51 |
| `BSPaywall` | 1458 | 8 |
| `BSAppShell` | 1526 | 4 |
| `BSPreviewBanner` | 1500 | 4 |
| `BSCosmicWordmark` | 297 | 3 |
| `BSWireHold` | 1428 | 1 |
| `BSWireLoading` | 231 | 1 |

⚠ **`BSTweaksPanel` (2076, 18 strings) is a dev-only panel — leave it English** and leave its
baseline line in place.

⚠ **This file needs NO window bridge.** Unlike the pros bundle (which needed the module-scope
non-hook `coachTr` because its roster helpers cannot hold a hook), `iosAppBroadsheetMain.jsx`
already imports the i18n singleton directly at lines 3–4 (`I18nextProvider`, `initI18n`,
`i18n as bsI18n`) and renders the provider at 2344. Import `useTr` from `../i18n/index.js`.

⚠ **And it probably needs no new NAMESPACE either.** `BSLanguagePicker.jsx` — the one localized
screen in this flow — does exactly this: `import { useTr } from '../i18n/index.js'`, then
`const { tr } = useTr('onboarding')`, with keys `lang.title` / `lang.subtitle` and one
cross-namespace `tr('common:action.continue')`. `onboarding` is already in the `NS` array and
already gated by the catalog-parity test, so the launch flow joining it costs no registration and
keeps the whole flow speaking one catalog. **The consequence to be deliberate about:** `onboarding`
is one of the two namespaces on the formal-`Anda` side of the Indonesian split (see §5), so cut 1
inherits that register rather than choosing one.

### Cut 2 — `BSSession`, the live workout player (74 strings)

In `iosAppBroadsheetClient.jsx`, which carries **~1,600 `tr()` calls** — which is exactly why a
per-file count reads that file as covered and hides this. The bridge already exists there.

### Cut 3 — the meal logger `BSLogMealFlow` (66 strings)

⚠ **Rename the parameter shadow first.** At ~line 2286 that component does
`getTracks().forEach(tr => tr.stop())` — a MediaStreamTrack, not the translator. Introduce a
real `tr` binding while that shadow stands and every `tr('…')` inside the callback becomes a
TypeError — and **parse, `tsc`, the suite and the build all pass on it**. The same class is live
in `BSPlaylistCard` (`list.map((tr, i) => …)`, a playlist track).

### Cut 4 — the `BSClientEat` partial (3 `tr()` against 62 hardcoded)

The worst number in the inventory, and it sits on a **primary tab**. A per-file count cannot see
it; a per-component *zero* check cannot either. It is only visible because the walk reports
partials as their own class. It moves out of `PARTIAL`, not `UNCOVERED`.

### How to close a cut out (the part that is not obvious)

1. **If you add a namespace, register it in BOTH** `mobile-app/src/i18n/index.js` (the `NS`
   array, line 12) **and** `tests/i18n-catalog-complete.test.mjs`. A namespace registered in only
   one of them **ships ungated** — the catalog-parity gate never sees it. (Cut 1 can reuse
   `onboarding` and skip this step entirely; cuts 2–4 land in modules that already have theirs.)
2. Author all **13** locales (`en es pt-BR fr de it id vi tr ha pcm ru uk`). Flat dotted keys.
   Brand nouns stay literal (Shape · Shape Score · Nora · Spotify · RPE · HRV · kcal · `HR`).
   Turkish never glues a case suffix onto a `{placeholder}` — but it **does** take one on a
   proper noun (`Shape'te` is correct; the "never after a brand noun" rule was mine and was
   wrong, and cost a garbled key once).
3. Run the tr-shadow greps in **both** forms:
   `grep -nE '(const|let|var) tr ='` **and** `grep -nE '\((tr)\)\s*=>|\((tr),\s*[a-z]'`.
4. **Edit the ratchet.** `tests/i18n-surface-inventory.test.mjs`: delete the component's line
   from `UNCOVERED` (line 235) or `PARTIAL` (278), and lower the exact assertions —
   `noneStrings` / `none.length`, or `partStrings` / `part.length`. They are pinned to the digit
   because membership alone cannot see a partial that hardcodes ten more strings.
5. ⚠ **Cut 3 also breaks a guard-the-guard.** Line 406 asserts
   `byKey.get('Client::BSLogMealFlow').tr === 0` with the reason attached. That assertion is
   correct today and must be updated when the component gains a real translator — do not delete
   it, re-point it.
6. Update `docs/WORKLOG.md` **and** `src/lib/warroom.ts` with the new measured numbers. Both
   currently say `125 of 358`.

⚠ **Scope one cut per PR.** The whole wave is ≈1,355 strings × 13 locales. The records are
explicit that firing it unattended "would be the opposite of what the measurement is for."

⚠ Translations are LLM-generated and ride the standing **human translation review** item.

⚠ Known residual in the instrument itself, stated so nobody re-derives it: **copy declared in a
data table and rendered by reference (`{W.label}`) is not attributed to its component** — a
limit of a lexical walk, which means the real gap is **larger** than reported, never smaller.
Attributing copy-keyed object properties was measured and rejected: it added **zero** components
and only inflated the count with demo fixtures.

## 4. The second search window (registered, not guessed)

#1953 shipped **one** ceiling: **60 per fixed window per member**, shared by
`search_shape_people` and `search_members` so a refused search cannot spend a second allowance
through the legacy fallback. A patient scraper under that per-minute rate is still unbounded
over an hour.

⚠ It is a **fixed** window, not rolling — it admits 60 at the end of one and 60 at the start of
the next, a 120 burst across the boundary. Do not describe it as rolling; that promises a
guarantee the counter does not make.

The plumbing for a second window already exists: `_rate_limit_bump` is one private fixed-window
helper both entry points call, and `check_rate_limit_self` takes a **SCOPE, never an identity**
(it derives the key from `auth.uid()`), so a longer window is a second scope on the same helper.

**What is missing is the number.** 60/min was a headroom judgement, safe only *because* every
caller debounces — a guard pins the debounce at each call site for exactly that reason. The
honest way to set either ceiling is a measured per-caller request trace. That measurement is the
work; the SQL is small.

## 6. Working notes that cost time to learn this session

- **`git fetch origin main && git rev-parse --short HEAD origin/main` fails** with "Needed a
  single revision". Split it into two commands. This recurred twice.
- **A rule can be wrong and still give the right answer on today's tree.** The old translator
  detector matched `/^(tr|[a-z]\w*Tr)$/` — a guess at a naming convention wearing a pattern. In
  `BSGrocery` it wrongly matched the *hook name* in exactly the component whose *binding*
  (`trG`) it wrongly missed, and the two errors cancelled. A mutation reverting to it **survived
  seven tests**. Only tightening to an exact count (`MktCoachCard` must read **1**) killed it.
  When a mutation survives, suspect the assertion before you conclude the fix was unnecessary.
- **A false exclusion is the direction that makes a guard lie.** Case-folding `hr` into the unit
  set collided with `HR` (heart rate) and silently dropped the only string `BSSplitsPage`
  hardcodes. The rule is now written at the set: a token is excluded only when it cannot also be
  an English word in running copy — which is why `in`, `am` and `pm` are deliberately *not*
  excluded.
- **An inventory guard needs a floor.** The first walk pruned the entire tree (the `Program`
  root's own `start` is 0, so a `n.start < component.start` range test excluded everything) and
  came back **empty** — every ratchet assertion would have passed vacuously, forever. The only
  reason it surfaced is an assertion that the walk must resolve >300 components. Silence and a
  clean tree are indistinguishable without one.
- **Mutation-test with `cp` backups, and commit the fix first.** `git checkout --` destroyed an
  uncommitted fix mid-batch once; the sanity case at the *end* of the batch is what caught it.
- **A Supabase probe can verify behaviour without leaving rows**: wrap the whole thing in a
  `DO $$ … raise exception 'PROBE(rolled back): %', r; end $$;` block — the result rides out in
  the error message and every write rolls back.
- **`get_advisors` output can exceed the tool's token limit** (264 KB here). Save it and read
  `d['result']['lints']` with a script instead.
