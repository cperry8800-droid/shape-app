### The pattern (any future i18n work)

- Components read via `useShapeTr()` → `tr('<ns>:<key>', {defaultValue})`.
  **NEVER shadow the theme `t`.**
- A new namespace must be registered in **BOTH** `mobile-app/src/i18n/index.js`
  **AND** `tests/i18n-catalog-complete.test.mjs` — miss the second and it ships
  **ungated**.
- Catalogs: `mobile-app/src/i18n/catalogs/<loc>/<ns>.json`, flat dotted keys,
  `keySeparator:false`.
- **Separate window-global bundles each need their OWN self-contained bridge**
  (marketplace · radio · calendar · habits · pros) — they can't import the
  client singleton.
- Gates: JSX parse · **tr-shadow grep** · catalog test 3/3 (key parity +
  ICU-placeholder preservation + ICU validity) · LF (CR=0) · PowerShell
  `VITE_BASE=/m/` build.

### Two gotchas worth keeping

- **tr-shadow crash class (no static gate catches it).** A pre-existing local
  `const tr = <something>` shadows the translator → runtime crash. Parse, tsc,
  tests and the build ALL pass. **Grep `const tr =|let tr =|var tr =` and
  confirm every one is `useShapeTr()`.**
- **The pros module needed a module-scope non-hook `coachTr()`** for pure
  helpers (`bsRosterSeverity`/`bsRowFromTriage`) that render verdict text but
  can't hold a hook. CodeRabbit caught the bug in it:
  `typeof window !== 'undefined' && window.ShapeI18n?.t?.(…)` short-circuits to
  boolean **`false`** (renders nothing) in a non-browser context — use a
  ternary yielding `undefined` so the `defaultValue` fallback fires.

### Process lesson (recorded)

For a big surface's multi-locale translation (coach = 835 keys × 12), dispatch
**direct per-locale-pair subagents from the main loop**. A single translation
agent that fanned out into **nested** sub-subagents produced **nothing** —
an 18-minute watch showed 0/12 files written. Nested spawning is unreliable
here; the direct agents each wrote their files correctly.

### Open (i18n)

- **Human translation review** — every non-EN catalog is LLM-generated and
  flagged throughout. A native-speaker pass is the standing follow-up before
  any non-EN locale is treated as final.
- **Reaction verbs deferred** — Spot/Beast/Respect… live in the shared
  `reactionVerbs.mjs` the **website also imports**; owner brand-voice call.

### ⚠ The reusable lesson from #1749 (closed) — read before touching a shared jsx

The first attempt also bumped `?v=` on the **69 pages** that load
`pageShell.jsx`. That made a **70-file PR**, and **CodeRabbit auto-skips any PR
over 50 files** ("Review skipped — Too many files!"). That's not a finding and
not a rate-limit that clears — it never reviews. Since the standing rule is
"wait for CodeRabbit unless the owner waives it per-task", the merge was
(correctly) blocked.

**The `?v` sweep was redundant anyway.** `scripts/build-newdesign.mjs` runs in
the Vercel buildCommand and **rewrites** each page's
`<script src="pageShell.jsx?v=X">` into `<script defer src="nd/pageShell…?v=<content-hash>">`
(`hash8(code)`). **Production's cache key is the content hash** — changing the
jsx cache-busts automatically and the hand-written `?v` is discarded. The manual
`?v` only affects the raw-babel dev path.

➜ **This corrects the older `AGENTS.md` / WORKLOG convention** ("bump the `?v=`
when you change a referenced `.jsx`"), which predates the #1726 precompile.
**Don't sweep `?v` across a shared jsx's consumers** — keep the PR to the jsx
file itself so CodeRabbit actually reviews it. #1749 was closed and reshipped as
a **1-file PR (#1750)** that CodeRabbit reviewed cleanly with 0 findings.
(A legacy root `public/*.html` outside the 74 precompiled newdesign pages may
still need a manual bump — if so, do it **byte-safe**: **17 newdesign HTML files
are `i/crlf`**, so `sed` strips their `\r`.)
