## 2. ⚠ THE REVIEW PROCESS CHANGED TWICE TODAY — read this before opening a PR

**CodeRabbit is the gate and runs EVERY round. Codex gets ONE round after CodeRabbit
clears.** Owner, mid-turn, twice: *"stop using codex for now, only coderabbit"*, then
*"do codex for one round moving forward"*.

The old rule — *fire Codex on every fix push* (owner, 2026-08-01) — is **dead**. It is
what made #1915 take five Codex rounds.

Four things about CodeRabbit that are not obvious and cost time today:

1. ⚠ **It does NOT auto-review this repo** — *"fewer than 10 stars"*. #1916 and #1917 both
   sat with **no review at all** while CI went green. Every round needs an explicit
   `@coderabbitai full review`, **including the first**. The recovery is always to trigger,
   never to wait.
2. ⚠ **`commented` is not a pass.** A pass is an **APPROVED** review on the head, or a
   zero-marker comment naming it. Measured over the last 18 merged PRs: `approved` 2,
   `clean` 1, `commented` **15**.
3. ⚠ **`Actionable comments posted: N` is NOT head-pinned.** That summary is *edited in
   place*. #1915 merged with it reading **2** while the head review was APPROVED with
   **zero** inline findings.
4. ⚠ **An empty-bodied `COMMENTED` review is its reply container, not a verdict** — it
   lands ~3 minutes *before* the APPROVED. Poll for a **settled** verdict (APPROVED /
   CHANGES_REQUESTED / inline findings on head), never for "a review exists". I sampled
   that gap, called the PR blocked, and invented a quota explanation for it. There was no
   quota problem: the fair-usage note CodeRabbit appends is boilerplate, and the *same*
   comment said the review had finished.

`prAllGreen` in `src/lib/console-flight.mjs` = CI green **AND** `approved`-or-`clean` on
**this** head **AND** not a draft. That file is **display only** — the merge itself goes
through the API against the three required checks.

## 3. What is open

Three items, all on the war room board (`src/lib/warroom.ts`), all routed to **you**:

- ⚠ **`writeUserGoal` swallows its upsert error**, so `notify_state` can fail to persist
  **silently**. This is why #1917's caps exist at all — an oversized `user_goals` blob
  would not fail loudly, it would lose the dedup state entirely. The caps bound what grows;
  they do not make a failed write visible. A serialized-payload ceiling was asked for in
  review and **deliberately not built**: it needs a byte budget I would be inventing, and it
  belongs with the silent-failure fix. ⚠ The same swallow applies to **every** `user_goals`
  writer — check the class, not the one call site. **Owner ruling needed.**
- ⚠ **An opt-out that never reaches the server is still not honoured by the cron.**
  `persistPrefs` declines to write when there is no `client_settings` document (offline,
  query error, never read), so an opt-out made then never leaves the device. Property of
  the writer, unfixable from the notify side.
- ⚠ **`BSClientHome` cannot be mounted in the jsdom harness** (a child resolves undefined —
  pre-existing, unrelated to this work). The check-in lead suppression is therefore proved
  by a named rule plus source guards, not end to end. Home is where `engineFlag`, the pref
  hooks and the bulletins all meet, and none of it is mount-covered.

**Not a blocker but owed:** the 12 non-English check-in strings shipped in #1917 are
**machine-authored** and want a native pass before launch — the standing caveat on this
i18n rollout.

## 4. ⚠ What the review rounds actually caught, kept because it is the useful part

- **A test I wrote to guard the cap's eviction direction could not fail.** The loop's last
  iteration leaves its item *queued*, so a re-offer was caught by the queue check and never
  reached the stamp — an inverted cap passed. I had also told the reviewer it would fail.
  Proved by mutation before believing the report; the test drains the queue first now.
- **I deleted a branch as unreachable on a because-clause that was the wrong part**,
  restored it the next round, then traced the reachability and found the argument *for*
  restoring it did not hold either. Kept the safer code, and labelled the test **defensive**
  rather than dressing an unreachable path up as a reproduction.
- **The same claim was fixed in the war room and left standing in the WORKLOG** for a full
  round — the class this repo keeps repeating. The corrected bullet now says it was wrong,
  because a record that quietly flips destroys the evidence that the process failed.
- **Half a bound is not a bound.** Capping each entry left the *number* of entries free.
- **Regex escapes collapsed again** — `\b` to a backspace, `[^\n]` to a real newline. Build
  with `chr(92)` and verify with `cat -v`. Third session running.
