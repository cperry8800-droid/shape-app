## The `public/m` saga (#1467) — and the durable fix

The branch was stuck because CI's **Mobile (build + public/m sync)** check failed and "just
re-submitting" couldn't fix it. The failure is the recursive `diff -qr mobile-app/dist public/m`,
NOT `npm ci`. Diagnosed via the GitHub Actions API (logs + the build's `dist` artifact, read with
git's stored PAT). Three stacked causes:

1. **Sourcemaps embed the build path.** Vite 8 uses **Rolldown**; `build.sourcemap` was `true`, and
   the `.map` files carried the absolute build path — `C:\Users\cperr\…` locally vs CI's
   `/home/runner/…`. So the maps never matched cross-platform. (Only this branch hits it: it's the
   one that bundles `three`/three-vrm via an absolute-path `resolve.alias`.)
2. **index.html line endings.** The working-tree `mobile-app/index.html` had drifted to **CRLF**
   while the committed blob is **LF** (what CI builds from); Vite preserved the EOLs, so the local
   build emitted an extra blank line.
3. **Windows ≠ Linux for the 3D bundle.** Even after the above, the Windows Rolldown build of the
   `three`/three-vrm JS chunks produced different bytes than CI's Linux build.

**Fix (in `mobile-app/vite.config.ts`):** `build.sourcemap: false` (also stops shipping ~5 MB of
maps + source to the public `/m/` URL) **+ a `transformIndexHtml(order:'post')` plugin that
normalizes the emitted HTML to LF on every platform.** And — the key operational fix — for each
`public/m`-touching PR, commit **CI's own Linux build** of `public/m`, pulled from a one-shot
`buildm` workflow's `dist` artifact, rather than a local Windows build.

## Architecture / things to know

- **`public/m` must be built on Linux to match CI.** This is the headline operational lesson. A
  Windows `npm run build` of the Nora (3D) bundle diverges from CI's Linux build — the Rolldown
  sourcemap build-path leak (now disabled) AND genuine Windows-vs-Linux nondeterminism on the
  `three`/three-vrm chunks. When a `public/m`-touching change is on a Windows machine, take CI's
  `dist` artifact (a build workflow → download → commit `public/m`) instead of a local rebuild.
  Simpler non-3D mobile PRs happen to match, which is why this only ever bit the Nora branch.
- **Merging multiple bundle PRs.** Each later `public/m`-touching PR must merge `main` in, then have
  `public/m` rebuilt fresh on Linux before merging, or `main`'s sync check breaks. (Done here for
  #1462 → #1466 → #1467, in that order; #1467 lands the `sourcemap:false` config.)
- **#1464 league RPC is intentionally service-role.** If a future review (CodeRabbit or human) flags
  it again, the answer is the rationale above — don't move it back under RLS.
- **GitHub ops without `gh`.** No `gh` CLI; PRs/merges/threads were driven via the REST + GraphQL
  APIs using the PAT in git's credential manager (`git credential fill`). Squash-merge =
  `PUT /repos/.../pulls/{n}/merge {merge_method:'squash'}`; resolve a thread =
  `resolveReviewThread(threadId)`; reply = `POST /repos/.../pulls/{n}/comments/{commentId}/replies`.
