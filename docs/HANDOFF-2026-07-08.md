## Self-serve training — the architecture you'll need

**Foundation (one migration, everything downstream lights up unchanged).**
`supabase-migrations/2026-07-08-self-authored-workouts.sql` (**APPLIED + live**):
- `client_workouts.trainer_id` → **nullable**. A self row is a `client_workouts`
  row with `trainer_id IS NULL` — nothing else new.
- **Client self-CRUD RLS**: INSERT/UPDATE/DELETE where `trainer_id IS NULL AND
  client_id = auth.uid()` (every `with check` pins both). Coach rows stay
  client-untouchable; self rows stay coach-untouchable — both directions.
- **`notify_on_client_workout` guarded** to `trainer_id IS NOT NULL` so a
  self-save (or a 100-row program materialization) never fires "New workout from
  your coach". Reproduced the trigger verbatim + added only the guard.

**Because self rows are just `client_workouts`, the Train deck, home hero,
calendar, live-session player, +10 `award_workout_session`, and the workout
auto-share (#1613) all read them with ZERO changes.**

**Three pure, unit-tested modules (the source-of-truth pattern; 24 new tests,
497 total green):**
- `mobile-app/src/services/starterTemplates.mjs` — `BS_STARTER_SESSIONS` (10
  one-tap sessions) + `BS_STARTER_PROGRAMS` (6 progressive programs: Marathon
  16wk · Half 12wk · 10K 8wk · Triathlon sprint 12wk · Hyrox 8wk · Strength
  block). `bsStarterProgram(id, weeks)` resolves a program to a concrete N-week
  schedule (clamps 1–26). Endurance builds ~10%/wk with a cutback every 4th week
  + a 2–3wk taper; Hyrox mixes lift + segment rows; tri rotates swim/bike/run +
  a brick. Shape validators `bsValidSessionShape` / `bsValidProgramShape` (the
  latter validates each move, post-review).
- `mobile-app/src/services/trainingBuilder.mjs` — `BS_BUILDER_CAP = 182`,
  `bsProgramFits(weeks, days)` (blocks over-cap, never truncates),
  `bsMaterializeProgram({name, weeks, startISO, runId})` → dated
  `client_workouts` insert-payloads stamped `payload.program:{id,name,week,day,
  weeks,runId}`, `bsRepeatSpec` (the one-row weekly-repeat shape carrying
  `payload.repeatDow`), `bsSlotRepeats(rows, mondayISO)` (7-slot week). Pure,
  timezone-free — caller supplies the start.
- `mobile-app/src/services/planOutline.mjs` — the coach `bsAssign*` outline
  parsers **extracted from `iosAppBroadsheetPros.jsx`** (the pros app imports
  them back — one implementation) + `bsMaterializeOutline({plan, startISO,
  weeks, runId})` for Start-this-plan (stamps `plan:<id>`).

**The data layer** (`mobile-app/src/services/shapeBackend.js`):
`window.ShapeSelfTraining = { saveSession, saveProgram, startPurchasedPlan,
remove, removeProgram, list }` (self rows via direct RLS-scoped inserts —
programs batch-insert in one round-trip) + `window.ShapeTrainingAI.draft`.
`startPurchasedPlan` is **atomic-in-effect**: the new block inserts first under
a fresh `runId`, then the prior run's rows delete — a mid-flow failure leaves
the old block intact, and a re-start never duplicates.

**The route** (`src/app/api/client/plan/route.ts`): windows dated rows
this-week-forward OR undated with **`nullsFirst: true`** (so a long program's
future weeks can't crowd the current week / repeat rows out of the 60-row cap);
passes through `repeatDow` / `seg` / `program` / `selfAuthored` per workout.
New route `POST /api/ai/draft-program` (registered in the War Room) — cloned
from `generate-plan`'s structured-output plumbing, **Bearer+cookie auth** via
`currentUser`, returns the exact builder PROGRAM shape; nothing persists until
the member saves; model-down → honest "unavailable".

**The UI** (`mobile-app/src/broadsheet/iosAppBroadsheetClient.jsx`):
- `BSBuildDoor` — Train's empty state for a signed-in member with no plan
  (`planLoaded && !liveProgram`): Sessions shelf · Programs shelf · Build your
  own · ✦ Draft · Open session. Signed-out keeps the demo deck.
- `BSWorkoutBuilder` — quiet Open-Ledger full-page form. SESSION (name ·
  discipline chips · weekday toggles → `repeatDow` · lift↔segment move rows) or
  PROGRAM (member-chosen weeks 1–26 OR a race date · week-by-week review · live
  `bsProgramFits` gate). The ✦ draft sheet lives inside it.
- `bsBuildTrainProgram` slots repeats (`bsSlotRepeats`) + renders segment rows;
  self days read **"Programmed by you"** (or the program name · Wn) with a teal
  spine — never a fabricated coach name. A repeat session shows **Edit · Yours**
  (threads `workoutId` → `saveSession` retires the old row on save).
- `BSSession` gained an **open mode** (empty start, inline move-naming, ＋ Add
  move) reached from the door + a deck text-action; saves through the identical
  path (+10, dedup, auto-share).
- `BSLibraryDetail` — a purchased training plan gets **START THIS PLAN →**
  (start-Monday picker + weeks) → `ShapeSelfTraining.startPurchasedPlan`.

**Review round (all 6 fixed before merge).** Codex 3×P2: draft-program
cookie-only auth (→ 401 on native) → `currentUser`; plan route nulls-last (→
repeat starvation) → `nullsFirst`; Edit·Yours duplicate → id threaded + old row
retired. CodeRabbit 2×Major + Trivial: OpenAI strict schema rejects
`minimum`/`maximum` (→ every draft errored) → removed, clamp in `sanitize()`;
`bsValidProgramShape` per-move validation; batch inserts. CodeRabbit APPROVED
on re-review; CI green ×3.
