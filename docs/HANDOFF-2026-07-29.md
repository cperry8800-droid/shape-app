## Architecture you will need

```
/api/trainer/week      week-shaped in  ─┐
/api/trainer/workout   session-shaped in ─┤─→ publishWeekForClient()  → publish_client_week
                       (widened via merge)                              (atomic, service-role)
```

- **`src/lib/week-publish-server.ts`** — `publishWeekForClient()`. The ONE
  implementation of read-history → judge → gate → write → record. Both routes call
  it. A second copy of a guardrail decision is how two doors start disagreeing about
  the same client's load.
- **`src/lib/week-merge.mjs`** (+ 15 fixtures) — widens a session-shaped write into
  the true week. **This is not a workaround, it is the contract:** the boundary
  REPLACES a client-week, so publishing one session would delete every other session
  that week AND hand the guardrail a week missing most of its load.
- **`src/lib/week-publish.mjs`** — the request contract (`normalizeWeekRequest`,
  `weekRequestHash`, `toProposedWeek`, `toWorkoutRows`). Its `PublishWeek` JSDoc
  typedef is importable from TS — import it, never mirror it.
- **`mobile-app/src/services/planOutline.mjs`** — the caller-side helpers
  (`bsAssignMonday`, `bsAssignKey`, `bsAssignWeeks`).

### Rules that fail silently, all now fixture-pinned

- **Grouping is by the session's OWN Monday.** A session in the wrong group is judged
  against the wrong week's load *and* caught in a replace that deletes a week it was
  never part of.
- **The capture stamp is all-or-nothing PER WEEK.** A partial stamp is malformed, one
  malformed row makes the whole evaluation `unknown`, and `unknown` never blocks — so
  stamping a half-filled week silently switches the guardrail OFF.
- **Past rows are never resubmitted.** The boundary refuses a past date and its
  replace clears only FUTURE rows. Carrying one fails the entire week on
  `past_session` — one logged Monday killing the publish. Today is not past.
- **Publish keys are content-derived**, so a retry is a replay. First call merges
  `[] + A → [A]`; the retry merges the stored `[A] + A → [A]`; same hash, same key.
  This is also what makes acknowledge-and-republish safe.
- **A rejection must arrive as WORDS.** Callers that predate the guardrail surface
  `error` on a non-2xx, so the reason goes there — a bare 409 strips the one sentence
  a coach can act on.

`applyAdjustRegeneration` (`shapeBackend.js:5789`) reads the coach's own future rows,
runs the pure planner `adjustRegen.mjs`, and calls `regenerate_client_workouts`

**Do not simply loop week-publishes.** Its atomicity is a real safety property
("never both plans, never zero") and N publishes forfeit it. **The design is:

## Traps this session paid for

- **The Edit/Write tools can write a `\uXXXX` escape as a LITERAL byte.** A NUL makes
  `git ls-files --eol` report `w/-text` — git treats the file as **binary** and the
  diff vanishes from review, while parse, tsc, tests and build all pass. Hit twice.
  Scan for CR *and* NUL after editing; write such sequences with a node script.
  The Bash tool also rejects a command containing control characters, so the fix
  script has to be a file.
- **PowerShell here-string syntax (`@'…'@`) in the Bash tool** mangles a commit
  message into a body starting with `@`. Use a heredoc.
- **A guard with no floor passes vacuously.** `tests/guardrail-rpc-args.test.mjs`
  asserts `checked >= 2`, and that is the only reason it failed rather than went
  quiet when the RPC calls moved into the shared module.
- **CodeRabbit findings on a plan can be stale against the implementation.** Verify
  each against the code before acting, and reply with evidence — silence reads as
  unaddressed. Two of the six in the last round were stale; the response is on
  PR #1848.
