on the exact claim the trigger comment asked it to check. **I reproduced it — it is real:**

```
DOB 2008-08-17 | instant 2026-08-17T00:30:00Z
America/Los_Angeles    localday 2026-08-16 | adult locally: false | JS adult: true  | ADMITS A MINOR EARLY
America/New_York       localday 2026-08-16 | adult locally: false | JS adult: true  | ADMITS A MINOR EARLY

```

The UTC day runs **ahead** of every zone west of UTC, so there `isMinorFromDob` declares
adulthood **before the member's local eighteenth birthday** — up to ~11h early
(Pacific/Niue, UTC−11). The header's claim that the asymmetry "only ever refuses for one
extra day rather than admitting a minor early" was **false west of UTC**, i.e. the comment
ruled out the exact thing the code was doing.

**Done:** the false safety claim is removed and replaced with the verified counterexample.
A one-directional guarantee in a comment is worse than the bug, because it tells the next
reader not to look.

**NOT done — deliberately, because it is a compliance decision on an applied migration:**

⚠ **`set_over_18()` has the IDENTICAL asymmetry** — it compares against `current_date`,
which is UTC. This is a property of the rule, not of the JS file, so **fixing only the JS
side puts the two gates back into disagreement about a real person** — the exact defect
the leap-year clamp in the same commit exists to prevent.

| Option | Behaviour | Cost |
|---|---|---|
| **(a) Conservative margin** — never adult until 18 in *every* zone | admits nobody early | **Breaks the documented contract** the vectors encode (`exactly 18 today is an ADULT`, matching `dob <= today - 18y`), refuses a genuine new adult up to ~1 day, and re-opens the JS↔SQL divergence by a day |
| **(b) Member-local day** — derive the cutoff from the member's own calendar day | correct in both directions | Needs a tz read in **both** callers (`computeMembership`, `refuseKnownMinor` — both query `profiles`, not `client_profiles`) **and a new migration** changing the trigger, on top of one already applied + production-verified |

The infrastructure for (b) exists: **`client_profiles.timezone`** (IANA, captured on app
open since 2026-06-27) and the Postgres helper **`shape_user_tz(uid)`**.

**"Which calendar day is authoritative for an age gate" is a jurisdictional question, not
a refactor** — so it is flagged, not drafted. Pick (a) or (b) and the fix follows in one

## What round 8 fixed (`53cdd22bf`)

**P1 — the age gate admitted a real minor for one day, and the two gates disagreed
about them.** `isMinorFromDob` derived its adult cutoff with
`Date.UTC(year - 18, month, day)`, which **rolls** an impossible anniversary forward
(Feb 29 → Mar 1), while Postgres `date - interval '18 years'` **clamps** it back
(Feb 29 → Feb 28). So on **Feb 29 of a leap year**, a member born exactly 18 years
earlier on **Mar 1** — 17 years and 364 days old — read as an **ADULT** in JS and a
**MINOR** to the `set_over_18()` trigger.

That is the unsafe direction, and it is the two derivations disagreeing about one
person, which is the entire reason the shared module exists. Both cutoffs were verified
against **production Postgres**: `2028-02-29 - interval '18 years'` = `2010-02-28`.
Recurs 2028, 2032, 2036…

The fix takes day 0 of the following month (= the last day of the intended one). Only
February can roll, but the guard is written generally.

⚠ **The 11 original vectors covered a leap-day BIRTHDAY and never a leap-day REFERENCE
DATE** — the one boundary the file was written to protect was the direction it did not
test. The new vector is **mutation-tested**: 12 pass with the clamp, **11 pass / 1 fail**
without it.

## Facts a new session needs before touching this area

- **`GATED_API_PREFIXES` has SEVEN entries** — `/api/client`, `/api/nutrition`,
  `/api/ai`, `/api/insights`, `/api/calendar`, `/api/conversations`, `/api/messages`.
  **Read the constant in `src/lib/supabase/middleware.ts`; never trust a prose copy.**
- **`refuseKnownMinor()` has exactly ONE caller** today: `src/app/api/radio/station/route.ts`.
- **`computeMembership` destructures `{ data }` and ignores `error`.** The Supabase
  client **resolves** rather than throws on query errors, so a faulted read yields
  `isMember:false` and exits via **402**, not 503. `refuseKnownMinor` by contrast reads
  `error` explicitly and **fails OPEN** by documented choice (it is a policy control, not
  a security boundary, and there is no second layer behind it).
- **`age-derive.mjs` is `.mjs` + a hand-written `.d.ts`** because `node --test` cannot
  import TypeScript. It imports nothing, which is what keeps it safe inside the edge
  proxy's import chain — `next build` listing `ƒ Proxy (Middleware)` is the proof it
  still bundles.
- **`node --test` prints `ℹ pass` / `ℹ fail`, not `# pass`.** A grep for `^# (pass|fail)`
  matches nothing and makes a mutation test look like it ran when it did not. This
  happened here and was caught only by re-running.
- **Node on Windows cannot read MSYS paths.** `/tmp/x` written by bash resolves to
  `C:\tmp\x` in Node and ENOENTs. `cd` into the scratchpad and use **relative**
  filenames.

## The pattern worth carrying out of this wave

the fix.
