## Architecture you'll need — sleep (Tier 1)

**The data flow (end-to-end, all field-name seams verified):**

1. **Mobile card** `BSDailyCheckinCard` (`mobile-app/src/broadsheet/iosAppBroadsheetClient.jsx`,
   ~14850) saves via `window.ShapeCheckin.log({ energy, hunger, sleepHours, sleepQuality: rested })`.
   - Device-first render: `sleepSynced` (set ONLY when today has device-only metrics —
     efficiency/RHR/HRV) → read-only `Xh Ym` + `bsSleepHM()` + the recovery snapshot.
     Otherwise editable hour chips (`setSleepHours(sel ? null : h)` toggle-to-clear) + the
     1–10 `Rested` row. **Key honesty rule:** hours alone never imply a device sync.
2. `shapeBackend.logCheckin` (`mobile-app/src/services/shapeBackend.js`, ~3308) forwards
   `sleepHours`/`sleepQuality` (camelCase) in the POST body.
3. `src/app/api/client/checkin/route.ts` validates (`sleepHoursOrNull` 0<h≤24 → 2dp;
   `clamp1to10` for quality) and writes `patch.sleep_hours`/`patch.sleep_quality` (snake_case)
   onto today's `daily_health_snapshot` (only when present).
4. `src/app/api/client/progress/route.ts` exposes `series.sleep`, `series.sleepQuality`,
   **`series.sleepEfficiency`** (added so the card can read TODAY's efficiency per-day),
   plus `series.restingHr`/`series.hrv`, and `kpis.sleepLatest/sleepEfficiency/hrvLatest`.
5. **Engine** — `mobile-app/src/services/signalsMap.mjs` exports the pure, tested
   `sleepRecoveryFromProgress(progress)` → `{ sleepHours: { avg7, lastNight, target: 7.5 } }`
   or `null`. `shapeSignals.js selfRecord` now fetches `ShapeProgress.progress()` and feeds
   `recovery` from it for signed-in members (was hardcoded `null` → the directive was DEAD).
   Consumed by `public/newdesign/dashSignals.js recoveryRead` → `buildDirective` (lever `sleep`).
6. **Coach** — `src/app/api/clients/[id]/shared-overview/route.ts` reads the client's
   `daily_health_snapshot` directly under the coach's session (RLS:
   `providers_read_subscriber_snapshots` — active sub gate; **no extra migration**), NEWEST 30
   then reversed to chronological, and returns `sleep = { latest, avg7, series7, efficiency,
   rhr, hrv }` (the recovery trio sourced from the SAME row as `latest`). Rendered on web
   `public/newdesign/coachClientDetail.jsx` (reuses the in-file `CKTrend`/`Card`/`CKSecHead`;
   `?v=20260626a` on `TrainerClient.html` + `NutritionistClient.html`) and mobile
   `iosAppBroadsheetPros.jsx` (`sleepRec` from the existing `ShapeCareTeam.overview` fetch).

**`daily_health_snapshot` sleep columns:** `sleep_hours`, `sleep_efficiency_pct`, `resting_hr`,
`hrv_ms` (device-sync, pre-existing) + new `sleep_quality` (manual 1–10 Rested, NOT in the
source-reconcile set). Reads use `select('*')` (migration-safe).

## Architecture you'll need — header avatars

`mobile-app/src/broadsheet/iosAppBroadsheetClient.jsx`: `const BS_HEADER_AVATAR = 34`
(module scope, `window.BS_HEADER_AVATAR` exported for the coach bundle). `BSSearchCorner`,
`BSHeaderTools`, `BSMeCorner` all default to it; the profile/coach mastheads reference it
directly for the search/pencil/gear/self-avatar cluster. **To change the one canonical
header avatar size, change this single constant.** Non-header avatars (feed/chat/list/hero/
settings) are intentionally NOT driven by it.
