## Habits

- App habit dates now use the current local calendar day instead of the fixed demo date. The page refreshes at day changes. Home future-day check-offs are disabled and guarded; historical entry remains available. Points match the backend's flat three points.
- `ShapeHabitsData.listStrict/action` uses the configured API origin and native bearer authentication, checks account ownership after responses, and propagates failures. The app habit hook distinguishes loading/error/ready, guards duplicate taps, applies confirmed changes, preserves failed drafts, and rejects stale account responses. Home reads back the confirmed list before updating its mirror.
- The habits API uses request-scoped authentication and explicit desired-state completion requests. Unique completion upserts and the existing score RPC identity make retries safe for the same desired state. Read failures stop writes; score failures remain visible. Revocation happens before deleting the completion so failed revocations retain an identity for retry. These are multiple database operations, not a new SQL transaction.

## Multi-dish timing and recovery

- `bsReplanCook` in `cookOrchestrator.mjs` retains completed steps and replans unfinished work around actual timer deadlines and station occupancy. Starting a late hold immediately recomputes the next actionable dish rather than retaining an obsolete blocked continuation. The interface displays the revised finish and remaining-dish spread. If an exact common finish is infeasible, it reports the gap rather than promising simultaneous completion.
- `bsCookBlockingHold` enforces recipe dependencies and configured burner/oven/prep capacity. Convenience timers do not block unrelated work. Soft timer starts cannot bypass a not-yet-due or occupied step.
- `cookBatchResume.mjs` validates account, timeline identities, timer deadlines and a 24-hour recovery window. The interleaved board persists dishes, cursor, timeline, timer ownership, completed records and start identity after interactions. Overnight recovery is allowed. Storage failures are shown; the key joins all three sign-out scrub surfaces.
- Final timers keep their deadlines and continue counting on the wrap screen. Leaving with active final timers preserves recovery. Reload/resume restores elapsed timer time instead of starting timers again.
