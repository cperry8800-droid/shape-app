## Watching and publishing

`public/newdesign/liveWatch.mjs` observes public and coach-only workout rows for both website and mobile viewers. It validates incoming payloads, filters unrelated DELETE events, polls every 15 seconds even while no workout exists, refreshes after reconnect/foreground, coalesces slow reads, and aborts reads after 20 seconds. Status distinguishes connecting/live/reconnecting/stale/idle. Account changes clear the snapshot and stop its observer.

`mobile-app/src/services/liveWorkoutPublisher.mjs` includes detailed coach input in change detection, so editing an already completed set republishes it. Writes coalesce on four-second intervals, unchanged heartbeats refresh every 15 seconds, failures retry, and original session start survives retries. Backend operations bind the initiating account/sign-out generation, abort stalled requests, and refuse cleanup from an obsolete account.

The extracted mobile `BSLiveWorkoutWatch.jsx` and desktop `coachLiveWorkout.jsx` show read-only set details, load units, status, elapsed time and queue. Desktop trainer/nutritionist consoles and client detail pages mount the same panel. Authenticated empty/error rosters do not substitute demo clients. The mobile trainer overview offers Watch for each active client. Mobile messages cover all 13 locales.

## Cue delivery

`ShapeCoachFeed.sendCue` uses the existing trainer/nutritionist console focus endpoint, bearer authentication on native, strict success checks, an abort deadline and account ownership guards. The endpoint retains relationship authorization. Pending sends are locked, failures retain the draft, and success is shown only after a confirmed save.

`subscribeWorkoutCues` watches the client's own `coach_focus_banners` rows since the active workout began, with eight-second polling, foreground/reconnect recovery, timeouts, deduplication and identity cleanup. `BSWorkoutCoachCue` displays and announces the cue inside the active workout, supports dismissal, and unmounts on completion.

Cues reuse the latest coaching focus note, which the composer explains. This is not a message history or delivery/read receipt. Detailed payloads retain up to 10 sets per exercise under the existing size limit; completion totals still count all sets. No migration was added.
