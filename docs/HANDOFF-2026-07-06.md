## Architecture you'll need

- **`mobile-app/src/services/scoreStanding.mjs`** — the ONE pure derivation both Score
  chart views + the verdict read: `bsScoreStanding(tiers, tierName, total)` →
  `{ laneIndex, laneCount, frac, pct, toNext, curThr, nextThr, topTier, atRisk, nextName }`.
  Mirrors the old hero frac math; **`atRisk` is computed before `frac`** so a top-tier
  member below the (high-water) floor clamps to `0%` empty instead of a forced full bar
  (CodeRabbit Major, caught + fixed in the build). 8 vectors in
  `tests/score-standing.test.mjs`, registered in the root `package.json` test list.
- **`BSScoreStandingChart({ tiers, tier, total, heat, t, seen, scale })`** (module scope,
  above `BSShapeScorePage`). ⚠ **The ladder-chart lesson (repeat of the terrain-ridge
  fix):** the SVG uses a `0 0 300 100` viewBox at `width:100%`, and the breathing you-dot +
  figure are an **HTML overlay** positioned by `youLeftPct` (% of full container width) —
  because SVG `<circle>` can't render the `bsSdPrBreath` box-shadow glow. For the overlay to
  stay ON the drawn lane, the ladder SVG carries **`preserveAspectRatio="none"`** (default
  `xMidYMid meet` letterboxes the 3:1 viewBox and the dot drifts off). The THIS-TIER view is
  pure HTML (hairline track + %-positioned dot), no SVG, no drift.
- **`BSStoreGlyph({ id, cat, size, color })`** + **`BSStoreImg`** — the photo/glyph
  fallback pair near the Store page.
- **Open Ledger kit reused as-is** (no new primitives): `BSTStationHead` / `BSTRedact` /
  `BSTLedgerStat` / `BSTerrainTabs` / `BSSdCountUp` / `useBSSdInView` / `bsSdReduced` /
  `bsSdSplitUnit`, keyframes via `bsInjectSessionDetailCss()` (call once in
  `React.useInsertionEffect`). **Heat = viewer tier** (`bsTierColor(profile.tier)`,
  line-only); **teal = live/action only** (Store CTAs + the one Score sign-in line);
  **rust = penalties, always named**. One breathing loop per page (Score you-dot only;
  Store none). `_bsUseLiveScore`, signed-out preview, and `bsRequireAccount` gating carry
  over verbatim.

single-file, well-scoped rebuild; reach for subagent-driven when tasks are independent and
the file surface is spread out.
