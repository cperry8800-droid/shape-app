## ⚠ Things that will bite you if you don't know them

- **A read that can't know is not a read that says "no".** `getUserGoals` resolves **NULL**
  for every can't-know case (no backend, not signed in, query error — it never rejects) and
  `{}` for a genuinely absent row. Flattening the two turned a failed read into "no
  preferences" and converged a member's OFF setting back to ON. The same class killed the
  wave's last defect: **`maybeSingle()` RESOLVES `{data:null,error}`** — it does not throw —
  so a failed profile read looked identical to an absent row, took the create path, and the
  upsert **overwrote** the existing row.
- **`saveUserGoals` UPSERTS the whole document.** Any whole-doc save issued before a pane's
  hydrate lands publishes that pane's DEFAULTS over everything else in the doc — units,
  privacy, meal times, phases. The guard belongs at the **writer**, not on the row a review
  happens to name.
- **`.slice(-7)` is not "the last 7 days".** `/api/client/progress` returns up to 400
  chronological snapshots with **no recency filter**. Anything reading a tail of that array is
  reading observations, not a window. ⚠ **`sleepRecoveryFromProgress` still does this** — it
  is registered, not fixed, because changing it alters shipped `sleep_low` firing.
- **A future-dated row is served forever by a floor-only window.** `/api/client/checkin` takes
  the day from the **request**, so `2099-01-01` is writable. The vitals window was only one of
  four victims — the same row was also `latest` sleep, the current RESTED rating and a
  readiness input. The ceiling is **tomorrow**, not today: `snapshot_date` is the member's
  LOCAL day, so a member ahead of UTC legitimately writes one.
- **Severity is computed before routing tags it.** `flags.length >= 2` → red runs **before**
  `readOnlyFlags` marks a non-owner's flag, so a nutrition-owned flag pushed to every role
  turned a **trainer** red. Route the flag out of the discipline that doesn't own it, don't
  patch the colour.
- **`/auth/callback` is not signup-only.** Password resets, magic links and email-change
  confirmations all exchange a code there carrying **SIGNUP metadata**. Provision fields only
  when the row lacks them.
- **`profiles.role` is NOT NULL with no default** (`email` is nullable — read the LIVE
  catalog, not the migration files). An INSERT omitting `role` fails 23502, and under the
  absence-refuses age policy a failed provisioning write is a **lockout**, not a retry.
- **Commit before mutation-testing.** Round 20's guard rewrite was reverted by a
  `git checkout --` while still uncommitted; the commit then reported *"1 file changed, 1
  insertion(+)"* while its message described changes that weren't in the diff. **Read the diff
  back.**

## Standing rules in force

- Merge gate is **two steps on the final head**: CI green **and** Codex clean. A clean Codex
  verdict is an **issue comment or a 👍**, never a review record — polling `/pulls/N/reviews`
  waits forever on a PR that already passed.
- Review quota is **owner-paid and finite**: audit locally first, batch fixes into **one**
  push, re-trigger rarely. Every push is a purchase.
- **Explicit paths on every commit** — never `git commit -a`, never a bare `git add .`.
- Branches are **kept** after a squash-merge, never deleted.
- Migrations are **owner-run**: post the raw GitHub link only.
- Flag anything needing counsel instead of drafting it.
